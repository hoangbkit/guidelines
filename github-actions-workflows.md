# GitHub Actions for Apple apps — manual CI and build releases

This is the standard setup for our Swift packages, iOS apps, macOS apps, and XcodeGen-based demo apps. **Nothing runs automatically**; CI and build releases are selected from GitHub Actions when needed. The build-release lane produces **unsigned** archives for local deployment/signing with `mycli`, not App Store/TestFlight releases.

## Required workflows

Create the following files in `.github/workflows/`:

| Name | File | Purpose | Permissions |
| --- | --- | --- | --- |
| Fast CI | `fast-ci.yml` | Quick tests/build on one Apple Silicon runner | `contents: read` |
| Full CI | `full-ci.yml` | Broader supported OS, CPU, simulator and demo coverage | `contents: read` |
| Build Release | `release.yml` (or `demo-release.yml` for package demos) | Publish selected unsigned app archives **and generated Xcode project ZIP** for `mycli` | `contents: write` |

**Non-negotiable trigger:** every file must declare only `on: workflow_dispatch`, with no `push`, `pull_request`, `pull_request_target`, `schedule`, `release`, `workflow_run` or tag automation. A PR does **not** run CI by itself under this policy. Trigger the appropriate job manually.

GitHub needs the dispatch workflow file on the **default branch** for its **Run workflow** entry to appear. Merge workflow definitions there first, then choose the branch/ref to run in the Actions UI (for example, `develop` or a feature branch). In each workflow, `actions/checkout` should operate on the selected ref, never a hardcoded `master`. Print the checked-out SHA.

General standards: explicit `timeout-minutes`; least privilege `permissions`; `concurrency` per branch with `cancel-in-progress: true` for CI, but **repository-wide** with `cancel-in-progress: false` for publishing; report `sw_vers`, `uname -m`, `swift --version` and `xcodebuild -version`. Select a known/tested Xcode version, checking that the path exists on each runner first. Runner image/Xcode versions change; adjust consciously.

## Optional private-repository authentication — include in every workflow

**Required standard step, optional secret:** after **every checkout** in **every job** that may fetch Swift packages, add the authentication step below, **before** `swift test`, `swift build`, `xcodebuild`, or dependency resolution. Include it in Fast CI, Full CI (every matrix/simulator job), and Build Release, even when the app currently has no private dependencies.

~~~yaml
      - name: Authenticate private GitHub repositories (if configured)
        shell: bash
        env:
          PRIVATE_REPO_TOKEN: ${{ secrets.PRIVATE_REPO_TOKEN }}
        run: |
          set -euo pipefail
          if [[ -z "$PRIVATE_REPO_TOKEN" ]]; then
            echo "PRIVATE_REPO_TOKEN is not configured; skipping private repository authentication."
            exit 0
          fi
          git config --global \
            url."https://x-access-token:${PRIVATE_REPO_TOKEN}@github.com/".insteadOf \
            "https://github.com/"
~~~

- **Secret present:** Git rewrites HTTPS `github.com` clone/fetch URLs to use the token, so SwiftPM/Xcode can access authorized private GitHub packages.
- **Secret missing or empty:** the step exits successfully without changing Git authentication. Public dependencies continue normally; a private dependency that actually requires credentials still fails explicitly.
- Create an Actions **repository secret** named `PRIVATE_REPO_TOKEN` in **the repository that runs the workflow**. For a disposable central CI repository, this means you only need to configure the secret once in that CI repository. Other app repositories can use the same YAML without defining the secret.
- Use a fine-grained personal access token with **Contents: Read-only**, scoped to the needed private dependency repositories. Restrict its lifetime and scope where practical; `All repositories` is simpler but grants broader access.
- The rewrite applies to HTTPS URLs beginning with `https://github.com/`; SSH URLs (`git@github.com:...`) are not covered. Never print the token, put it into release artifacts, or commit it to the repository. GitHub-hosted runners discard the job environment after completion.

This step is deliberately a shell guard instead of a step-level `if`; missing Actions secrets evaluate to an empty string. It keeps the same workflow usable with and without the secret.
## Preparation for a clean checkout

1. Check in `Package.swift` or an XcodeGen `project.yml`; include reproducible dependency pinning where appropriate. Do not rely on a generated, developer-local `.xcodeproj`.
2. Validate each target/scheme. XcodeGen-created projects need **shared schemes** in `<App>.xcodeproj/xcshareddata/xcschemes/`; verify they are generated by the checked-in spec. Use an iOS and macOS scheme for dual-platform builds.
3. Stage **test fixtures** for Fast CI. For apps with bundled AI models/voices, cache real resources separately and verify checksums/manifest contents. Stage required directories **before `xcodegen generate`** if the spec references them.
4. Ignore generated DerivedData, staged build files and `.xcarchive` directories. The generated `.xcodeproj` must still be published **as an asset** in every build release; there is no need to commit it.
5. CI should not need signing certificates, private keychains, App Store Connect tokens or provisioning profiles. Ensure GitHub Actions is enabled in repo settings.
6. Cache SwiftPM `SourcePackages` keyed by OS/arch/Xcode/dependency lockfile where beneficial; do not blindly cache multi-GB DerivedData. Keep model/voice cache keys independent and versioned, and validate their contents.

## Fast CI

One `macos-26` Apple Silicon job; aim to run package tests or build/smoke test the principal app with small fixtures. Avoid model downloads and exhaustive OS matrices.

**Example `fast-ci.yml` for a Swift package:**

~~~yaml
name: Fast CI
on:
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: fast-ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  test:
    runs-on: macos-26
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v6
      - name: Authenticate private GitHub repositories (if configured)
        shell: bash
        env:
          PRIVATE_REPO_TOKEN: ${{ secrets.PRIVATE_REPO_TOKEN }}
        run: |
          set -euo pipefail
          if [[ -z "$PRIVATE_REPO_TOKEN" ]]; then
            echo "PRIVATE_REPO_TOKEN is not configured; skipping private repository authentication."
            exit 0
          fi
          git config --global \
            url."https://x-access-token:${PRIVATE_REPO_TOKEN}@github.com/".insteadOf \
            "https://github.com/"
      - name: Toolchain
        run: |
          uname -m
          sw_vers
          xcodebuild -version
          swift --version
      - name: Package tests
        run: |
          set -euo pipefail
          swift package dump-package >/dev/null
          swift test --parallel
~~~

For an **iOS app**, replace `swift test` with: stage fixtures; `brew install xcodegen` (if absent); `xcodegen generate --spec project.yml`; run a Debug simulator **build** with `-destination 'generic/platform=iOS Simulator'` and `CODE_SIGNING_ALLOWED=NO`, plus focused **tests** if available. For `xcodebuild test`, dynamically discover a real available simulator and use `-destination "platform=iOS Simulator,id=<UDID>"`; the generic destination is only for build. For a **macOS app**, build `-destination 'platform=macOS,arch=arm64'` and optionally run a small stable unit/UI smoke suite. Upload `.xcresult` when useful, including on failure. Do not make Fast CI silently succeed without testing its declared responsibility.

## Full CI

Keep manual dispatch. This is an intentional, more expensive pre-merge/pre-release verification lane. Test actual supported versions, architecture, demos, assets and regressions — not merely repeat Fast CI.

Suggested matrix for packages/macOS apps that support these OS/CPU combinations:

~~~yaml
name: Full CI
on:
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: full-ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  macos:
    strategy:
      fail-fast: false
      matrix:
        include:
          - { runner: macos-15, arch: arm64 }
          - { runner: macos-15-intel, arch: x86_64 }
          - { runner: macos-26, arch: arm64 }
    runs-on: ${{ matrix.runner }}
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v6
      - name: Authenticate private GitHub repositories (if configured)
        shell: bash
        env:
          PRIVATE_REPO_TOKEN: ${{ secrets.PRIVATE_REPO_TOKEN }}
        run: |
          set -euo pipefail
          if [[ -z "$PRIVATE_REPO_TOKEN" ]]; then
            echo "PRIVATE_REPO_TOKEN is not configured; skipping private repository authentication."
            exit 0
          fi
          git config --global \
            url."https://x-access-token:${PRIVATE_REPO_TOKEN}@github.com/".insteadOf \
            "https://github.com/"
      - name: Run repo-specific tests and macOS demo
        shell: bash
        run: |
          set -euo pipefail
          uname -m
          xcodebuild -version
          swift package dump-package >/dev/null
          swift test
          # ADD: XcodeGen + native macOS app/demo build and resource checks.
  # ADD: separate macos-26 iOS Simulator build/test job when iOS is supported.
~~~

This is a **skeleton**, not complete full coverage on its own. Add `swift build -c release` for packages; build the macOS demo on its supported architectures; build/test the iOS demo on an available iOS Simulator; verify assets, entitlements, resources and app startup where applicable. A simulator **build** may use `generic/platform=iOS Simulator`, while **test** needs an actual device destination. Use separate DerivedData paths per job. Only include Intel/older macOS when actually supported; do not mask legitimate errors with `continue-on-error`. Pin Xcode to a version installed on **every selected runner** and check it first.

## Build Release: contract for mycli

This workflow is **not a production signing/distribution pipeline**. It builds the chosen branch/configuration, then publishes a **GitHub prerelease** whose name/tag is `mycli-build-<run-id>-<attempt>`. The unique namespace keeps disposable builds distinct from real version releases.

Required outputs:

| Selected platform | GitHub Release assets |
| --- | --- |
| iOS | `App-iOS-release-unsigned-mycli-build-....xcarchive.zip` + `App-xcodeproj-mycli-build-....zip` |
| macOS | `App-macOS-universal-release-unsigned-mycli-build-....xcarchive.zip` + `App-xcodeproj-mycli-build-....zip` |
| both | Both unsigned `xcarchive.zip` files + the **one** generated project ZIP |

Use Debug/Release as user-selectable configuration (Release default). One configuration per run is simplest. Multiple configurations are fine only if `mycli`'s asset picker and naming distinguish them. Package demos can use `demo-release.yml` but must meet the same artifact contract.

**Example `release.yml`:** replace `MyApp`, schemes, bundle IDs, spec path, resource staging/verification and deployment targets to suit the repository. Remove an unsupported platform's input and steps instead of producing a fake artifact.

~~~yaml
name: Build Release
on:
  workflow_dispatch:
    inputs:
      platform:
        description: Platform
        required: true
        type: choice
        default: both
        options: [iOS, macOS, both]
      configuration:
        description: Configuration
        required: true
        type: choice
        default: Release
        options: [Debug, Release]
permissions:
  contents: write
concurrency:
  group: mycli-release-${{ github.repository }}
  cancel-in-progress: false

jobs:
  build:
    runs-on: macos-26
    timeout-minutes: 90
    env:
      APP: MyApp
      PROJECT: MyApp.xcodeproj
      IOS_SCHEME: MyApp-iOS
      MAC_SCHEME: MyApp-macOS
      IOS_BUNDLE_ID: com.example.myapp
      MAC_BUNDLE_ID: com.example.myapp
    steps:
      - uses: actions/checkout@v6
        with:
          ref: ${{ github.ref }}
          fetch-depth: 0

      - name: Authenticate private GitHub repositories (if configured)
        shell: bash
        env:
          PRIVATE_REPO_TOKEN: ${{ secrets.PRIVATE_REPO_TOKEN }}
        run: |
          set -euo pipefail
          if [[ -z "$PRIVATE_REPO_TOKEN" ]]; then
            echo "PRIVATE_REPO_TOKEN is not configured; skipping private repository authentication."
            exit 0
          fi
          git config --global \
            url."https://x-access-token:${PRIVATE_REPO_TOKEN}@github.com/".insteadOf \
            "https://github.com/"

      - name: Generate Xcode project
        shell: bash
        run: |
          set -euo pipefail
          echo "Commit: $(git rev-parse HEAD)"
          xcodebuild -version
          # ADD: exact tested Xcode selection, if required.
          # ADD: download/stage/verify selected offline resources FIRST.
          brew install xcodegen
          xcodegen generate --spec project.yml
          test -f "$PROJECT/project.pbxproj"
          test -f "$PROJECT/xcshareddata/xcschemes/$IOS_SCHEME.xcscheme"
          test -f "$PROJECT/xcshareddata/xcschemes/$MAC_SCHEME.xcscheme"

      - name: Build identity and Xcode project ZIP
        id: meta
        shell: bash
        run: |
          set -euo pipefail
          tag="mycli-build-$GITHUB_RUN_ID-$GITHUB_RUN_ATTEMPT"
          echo "tag=$tag" >> "$GITHUB_OUTPUT"
          echo "sha=$(git rev-parse HEAD)" >> "$GITHUB_OUTPUT"
          mkdir -p artifacts
          ditto -c -k --sequesterRsrc --keepParent "$PROJECT" \
            "artifacts/${APP}-xcodeproj-${tag}.zip"
          unzip -tq "artifacts/${APP}-xcodeproj-${tag}.zip"
          unzip -Z -1 "artifacts/${APP}-xcodeproj-${tag}.zip" \
            | grep -Fx "$PROJECT/project.pbxproj"

      - name: Archive unsigned iOS device app
        if: ${{ inputs.platform == 'iOS' || inputs.platform == 'both' }}
        shell: bash
        env:
          CONFIG: ${{ inputs.configuration }}
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          set -euo pipefail
          archive="$RUNNER_TEMP/${APP}-iOS.xcarchive"
          xcodebuild -project "$PROJECT" -scheme "$IOS_SCHEME" \
            -configuration "$CONFIG" -sdk iphoneos \
            -destination 'generic/platform=iOS' \
            -derivedDataPath "$RUNNER_TEMP/Derived-iOS" \
            -archivePath "$archive" \
            CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO archive
          test -f "$archive/Info.plist"
          shopt -s nullglob
          apps=("$archive"/Products/Applications/*.app)
          test "${#apps[@]}" -eq 1
          bundle=$(/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' \
            "${apps[0]}/Info.plist")
          test "$bundle" = "$IOS_BUNDLE_ID"
          # ADD: validate bundled models, resources, icon and entitlements.
          lower=$(echo "$CONFIG" | tr '[:upper:]' '[:lower:]')
          ditto -c -k --sequesterRsrc --keepParent "$archive" \
            "artifacts/${APP}-iOS-${lower}-unsigned-${TAG}.xcarchive.zip"

      - name: Archive unsigned universal macOS app
        if: ${{ inputs.platform == 'macOS' || inputs.platform == 'both' }}
        shell: bash
        env:
          CONFIG: ${{ inputs.configuration }}
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          set -euo pipefail
          archive="$RUNNER_TEMP/${APP}-macOS.xcarchive"
          xcodebuild -project "$PROJECT" -scheme "$MAC_SCHEME" \
            -configuration "$CONFIG" -sdk macosx \
            -destination 'generic/platform=macOS' \
            -derivedDataPath "$RUNNER_TEMP/Derived-macOS" \
            -archivePath "$archive" ARCHS="arm64 x86_64" \
            ONLY_ACTIVE_ARCH=NO \
            CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO archive
          test -f "$archive/Info.plist"
          shopt -s nullglob
          apps=("$archive"/Products/Applications/*.app)
          test "${#apps[@]}" -eq 1
          bundle=$(/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' \
            "${apps[0]}/Contents/Info.plist")
          test "$bundle" = "$MAC_BUNDLE_ID"
          exe=$(/usr/libexec/PlistBuddy -c 'Print :CFBundleExecutable' \
            "${apps[0]}/Contents/Info.plist")
          archs=$(lipo -archs "${apps[0]}/Contents/MacOS/$exe")
          [[ " $archs " == *" arm64 "* ]]
          [[ " $archs " == *" x86_64 "* ]]
          # ADD: validate bundled models, resources, icon and entitlements.
          lower=$(echo "$CONFIG" | tr '[:upper:]' '[:lower:]')
          ditto -c -k --sequesterRsrc --keepParent "$archive" \
            "artifacts/${APP}-macOS-universal-${lower}-unsigned-${TAG}.xcarchive.zip"

      - name: Verify requested assets
        shell: bash
        env:
          PLATFORM: ${{ inputs.platform }}
          CONFIG: ${{ inputs.configuration }}
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          set -euo pipefail
          project="artifacts/${APP}-xcodeproj-${TAG}.zip"
          test -s "$project"
          unzip -tq "$project"
          for scheme in "$IOS_SCHEME" "$MAC_SCHEME"; do
            unzip -Z -1 "$project" \
              | grep -Fx "$PROJECT/xcshareddata/xcschemes/$scheme.xcscheme"
          done
          lower=$(echo "$CONFIG" | tr '[:upper:]' '[:lower:]')
          ios="artifacts/${APP}-iOS-${lower}-unsigned-${TAG}.xcarchive.zip"
          mac="artifacts/${APP}-macOS-universal-${lower}-unsigned-${TAG}.xcarchive.zip"
          if [[ "$PLATFORM" == iOS || "$PLATFORM" == both ]]; then
            test -s "$ios"
          else
            test ! -e "$ios"
          fi
          if [[ "$PLATFORM" == macOS || "$PLATFORM" == both ]]; then
            test -s "$mac"
          else
            test ! -e "$mac"
          fi
          shopt -s nullglob
          assets=(artifacts/*.zip)
          expected=2
          [[ "$PLATFORM" == both ]] && expected=3
          test "${#assets[@]}" -eq "$expected"
          for asset in "${assets[@]}"; do
            unzip -tq "$asset"
            bytes=$(stat -f%z "$asset")
            (( bytes > 0 && bytes < 2147483648 ))
          done
          ls -lh artifacts

      - name: Publish disposable GitHub prerelease
        shell: bash
        env:
          GH_TOKEN: ${{ github.token }}
          TAG: ${{ steps.meta.outputs.tag }}
          SHA: ${{ steps.meta.outputs.sha }}
        run: |
          set -euo pipefail
          gh release create "$TAG" artifacts/*.zip \
            --target "$SHA" --title "$TAG" --prerelease --generate-notes
~~~

**Important for nested demo projects:** `ditto --keepParent` stores the Xcode project **basename** as the ZIP's root, not `Demo/<Name>.xcodeproj` or `Examples/<Name>.xcodeproj`. In that case, replace the `grep -Fx "$PROJECT/..."` assertions with `grep -Fx "$(basename "$PROJECT")/..."`. The artifact must contain `project.pbxproj` and shared schemes. Never substitute a ZIP of `project.yml`, an `.app` only, or an Actions-only artifact for the required GitHub Release assets.

This template is a starting implementation, **not an assertion** that all apps have the same scheme names, resource layout, minimum OS, signing expectations or capabilities. Use real-resource staging and integrity checks for device-deployable archives, and verify the generated Xcode project carries the settings `mycli` needs to resolve the development team. Local `mycli` performs signing/export/deploy, not GitHub Actions.

## CI minutes, reliability and integrity

- **Fast:** one relevant runner, Debug + fixtures, shortest meaningful tests. Avoid re-downloading heavyweight models.
- **Full:** matrix only over supported OS/CPU combinations. Run real iOS simulator tests on Apple Silicon and keep macOS UI smoke tests narrowly scoped; do not hide failures using `continue-on-error`.
- **Build Release:** cache model/voice resources by stable version/manifest/checksums; validate the **actual archived app**, not just source directories. Use isolated iOS/macOS DerivedData and shared SwiftPM downloads where useful.
- Never embed credentials, certs, secrets, private user data or unlicensed assets in prerelease ZIPs. CI failure should be explicit, not silently fall back to missing resources.
- Confirm GitHub Release per-file **2 GiB** limit before publishing. A ZIP named like an `.xcarchive` is not sufficient: verify structure, exactly one app, bundle identifier, icons/resources and macOS CPU slices.

## Acceptance checklist

- [ ] Exactly three manual-only workflows (or equivalent app-specific names) visible in GitHub Actions.
- [ ] Selected branch and commit are logged; no hardcoded checkout of another branch.
- [ ] Every build/test/release job has the optional `PRIVATE_REPO_TOKEN` step immediately after checkout; it skips safely if the secret is not configured.
- [ ] Fast CI passes from a clean checkout; Full CI provides genuinely broader supported coverage.
- [ ] Release platform/configuration selectors produce **only** the requested unsigned archive(s).
- [ ] iOS archive is a **device** `.xcarchive` (not a simulator build), with correct bundle ID/resources.
- [ ] macOS archive is an `.xcarchive` and includes both `arm64` and `x86_64` when universal.
- [ ] **Every** release includes an independently downloadable ZIP of the **generated Xcode project**, with `project.pbxproj` and the shared schemes.
- [ ] ZIP integrity, contents, expected asset count and per-file size checked before publication.
- [ ] Prerelease uses a unique `mycli-build-` tag pointing at selected SHA; not mixed with product version tags.
- [ ] At least one archive can be downloaded and signed/deployed locally with `mycli`. This verification is still required after workflow YAML review.
